# Цели в Яндекс.Метрике — реестр и правило для нового функционала

Счётчик **Mngment.ru — ID 111721939**. Все цели ниже, кроме автоцелей, реализованы вручную через `ym(111721939, 'reachGoal', '<event>', {...})` — вызовы уже зашиты в [script.js](../script.js), модули 2, 2.1, 11, 12, 13. Сами цели в интерфейсе Метрики (Настройка → Цели → «Целевое событие») заводятся один раз вручную — это не автоматизировано.

## Автоцели (Яндекс завёл сам, ничего делать не нужно)

| Название | Тип | Что ловит |
|---|---|---|
| Автоцель: отправка формы | form | Успешная отправка любой формы на сайте |
| Автоцель: заполнил контактные данные | contact_data | Ввод телефона/email в поле формы |
| Автоцель: отправил контактные данные | contact_data_sent | Отправка формы с контактными данными |
| Автоцель: переход в мессенджер | messenger | Клик по ссылке на Telegram/WhatsApp |
| Автоцель: клик по номеру телефона | phone | Клик по `tel:` ссылке |
| Автоцель: клик по email | email | Клик по `mailto:` ссылке |

## Ручные цели (JS-события из script.js)

| № | Событие (`event` в reachGoal) | Название цели в Метрике | Параметры | Что ловит |
|---|---|---|---|---|
| 1 | `cta_click` | Клик по CTA-кнопке | `cta_text`, `cta_url` | Клик по любому `.btn-primary`, `.btn-outline`, `.btn-accent` — все кнопки-призывы к действию |
| 2 | `case_read_click` | Клик «Читать кейс» | `case_url` | Клик по ссылке `.btn-link`, ведущей на `/cases/...` |
| 3 | `db_item_click` | Клик по карточке базы | `db_name` | Клик по элементу `.db-item` в каталоге готовых баз (`/services/parsing-lidogeneraciya.html`) |
| 4 | `burger_menu_click` | Клик по бургер-меню | `state` (open/close) | Открытие/закрытие мобильного меню |
| 5 | `filter_click` | Клик по фильтру блога/кейсов | `filter_value`, `filter_label` | Переключение категории в списке статей блога или кейсов |
| 6 | `modal_close_click` | Закрытие модалки заказа базы | `modal` | Крестик закрытия окна заказа базы |
| 7 | `manager_widget_toggle_click` | Открытие виджета «Написать менеджеру» | `state` | Клик по плавающей кнопке 💬 |
| 8 | `manager_widget_option_click` | Выбор канала в виджете менеджера | `channel` | Клик по Telegram/WhatsApp/Email внутри виджета |
| 9 | `contact_click` | Клик по телефону/email со страницы | `channel`, `page` | Дублирует автоцели телефона/email, но с точным путём страницы — для разбивки по странице без Вебвизора |

Разбивка по конкретной кнопке/базе/каналу — не отдельными целями, а через отчёт «Конверсии» → выбрать цель → «Группировка» → «Параметры визита».

## Правило: новый функционал → новая цель

Если правка на сайте добавляет новый кликабельный элемент, представляющий пользовательское действие (кнопка, ссылка-CTA, форма, модалка, виджет, переключатель) — он **не** покрывается существующими целями автоматически, если только не подпадает под уже существующий селектор из таблицы выше (например, новая кнопка с классом `.btn-primary` уже попадёт в `cta_click` без доработок).

Порядок действий при обнаружении нового типа конверсионного элемента, не покрытого таблицей:

1. Явно сообщить об этом в ответе пользователю: что добавлен новый элемент, какой JS-event и параметры для него предлагаются.
2. Добавить `trackGoal('<новое_событие>', {...})` в script.js рядом с обработчиком клика (по аналогии с уже существующими модулями), задеплоить.
3. Обновить таблицу выше новой строкой.
4. Отправить письмо на **send@mngment.ru** через MCP-инструмент `timeweb-mail` с темой `Новая цель Метрики: <название>` и телом, в котором: что за элемент, какой event и параметры, и напоминание вручную завести цель в интерфейсе Метрики (Настройка → Цели → «Целевое событие», идентификатор — то самое значение `event`).

Не пропускать пункт 4 даже для мелких на вид добавлений — иначе цель остаётся только в коде, но не в интерфейсе Метрики, и конверсия фактически не считается нигде в отчётах.
